# 任务完成判据：调研结论与我们的设计（2026-10-13）

> 论文原文摘录、开源项目考究与创新点设计已归档到资料库：[`research/README.md`](research/README.md)
> （每条带验证状态：✅ 已核验 / ⚠️ 仅摘要 / ❓ 未核验；BibTeX 见 `research/references.bib`）。

> 问题：**"怎么就算做到了"由谁定？** 我们先后试过两版都不对——运行时写死常数（把靠近类
> 任务的标准强加给所有任务）、运行时按任务类型兜底（还是运行时替任务发明标准）。
> 操作员要求去调研机械臂 VLA 那边怎么做，本文是结论与落地。

## 1. 调研：开源 VLA 项目怎么做终止判定

结论一句话：**没有任何可查证的开源 VLA 自己发"完成"信号；终止一律是外部的。**

| 项目 | 策略发停止信号？ | 独立验证器？ | 判据由谁写 | 成功谁打分 | 执行/重观察节奏 |
|---|---|---|---|---|---|
| OpenVLA / OFT | 否（"只生成动作"） | 无 | benchmark/实验者 | LIBERO 环境谓词；真机人工 0/1/0.5 | 单步；OFT 块长 8/25 |
| openpi（π0 / π0.5 / π0-FAST） | 否（π0.5 只输出子任务文本） | 无 | 人工评分要点 | 评分要点含部分分（1.0=完全成功） | 动作块 H=50，每 16/25 步重推理；`max_episode_steps=1000` |
| Octo | 否 | 无 | benchmark/人工 | 试验成功率 | 块长 4，可选"只执行第一步"或时序集成 |
| RDT-1B | 否 | 无 | benchmark/人工 | 成功率 | 预测 64 步 |
| GR00T N1/N1.5 | 否 | 无 | benchmark/人工 | 仿真谓词 | 动作时域 16→40，执行 8/16 |
| LeRobot | 策略无；框架有 | 无内置 | 环境作者 | `info["is_success"]`（环境真值） | `while not done and step < max_steps`，硬上限 |
| CoT-VLA | 否 | 无 | benchmark | 成功率 | 视觉 CoT 预测子目标图，块间重观察 |
| **SayCan** | **是**（计划级）：计划以 "Done" 步收尾，循环"直到输出终止步" | 只有可行性价值函数（不是成功检测器） | LLM 写计划 | 人工（101 任务 84% 计划/74% 执行） | 技能级各自终止 |
| **Inner Monologue** | 由反馈下的规划器决定（继续/重试/重规划/**停止**） | **有**：学习出来的成功检测器，结果作为文本反馈注入 | 检测器训练得到 | 任务完成率 | 每个技能后重规划 |
| Code as Policies / VoxPoser | 隐式（生成的程序跑完） | 无 | LLM 写整段程序（含检查） | 仿真/人工 | 程序内闭环 |
| **ReKep** | **是**（按阶段）：`距离(e_t,e_g) < ε` 则进入下一阶段；违反路径约束则回退 | 无 VLM 验证器；约束跟踪即检查器 | GPT-4o 为每个阶段写 Python 约束函数 | 人工操作员打分 | 实时关键点跟踪 |
| MOKA | 否（"执行到多阶段任务结束"，每阶段 100 步上限） | 无 | VLM 拆子任务+关键点 | 人工专家 | 子任务间重新问 VLM |
| LLM+P（PDDL） | 经典规划器到达目标公式即结束 | 规划器校验 | LLM 写 PDDL 目标谓词 | 目标可达性/最优性 | — |
| ProgPrompt | 隐式（程序结束） | 解释器：断言检查前置条件并触发恢复 | LLM 写断言；函数名即任务规格 | VirtualHome 状态成功率 | — |
| VLA-SCT（2026） | 额外加一个终止模块 | 训练无关的自纠正环 + "条件逻辑终止" | 启发式模块 | LIBERO 提升 | 论文明确写：VLA"缺乏可靠识别任务完成的能力"，导致**冗余动作与超时** |
| RoboChemist（2025） | 否 | **是**：VLM 当监控器判成功与合规 | VLM 监控 | 成功率+合规分 | 双环：VLM 规划 → VLA 执行 → VLM 复检 |
| SuccessVQA（2023） | — | 训练过的 VLM 成功检测器 | 人工奖励标注定义成功 | 分布偏移下优于定制奖励模型 | — |

## 2. 可直接借鉴的机制（按适配度排序）

1. **判据留在计划里，不放在运行时**（ProgPrompt 的断言 / ReKep 的约束函数 / VLA-SCT 的终止逻辑 /
   LLM+P 的目标谓词都是这么做的）。运行时只认识一组**可评估的原语**。→ 我们已照此改造。
2. **两层判据**：能用载具自身状态的（`landed`、`armed`、位置）就**别问视觉**；只有视觉能回答的
   （"是不是穿过了门框""标记是否居中"）才交给 VLM。→ 我们的判据表已按此分类。
3. **判据是一个元组，不是一个名字**：`(metric, params, tolerance, hold_for, timeout, on_unknown)`。
   `hold_for`（持续成立才作数）是文献里防"过早收工"和"来回跳"的标准手段。→ **本轮已实现
   `hold_s`**（默认 0 = 单次成立即可）。
4. **词汇表封闭但可扩展**：固定枚举 + 计划写的数值参数（安全、无需训练）；不要"每类任务一段代码"。
   未来可加"计划写问题、VLM 回答"的语义判据（RoboChemist 的 VLM 监控、SuccessVQA 的思路）。
5. **进度分与停止谓词分开**：π0.5 用带部分分的评分要点衡量进度，用严格谓词决定停止。一个数字
   同时兼两职，最后一定会退化成"任务类型默认值"这种糊法。
6. **检查要有预算**：确定性判据每次评估、VLM 判据只在阶段边界或异常时问、永远留一个硬超时
   （上面每个项目都有）。→ 我们有 `max_steps`。
7. **VLM 判据要标定、要留"未知"**：VLM 假阳性会提前结束任务（这是被实测过的失效模式），
   所以"未知/含糊"应当按"再观察一次"处理，而不是硬判成功或失败。

## 3. 我们的设计（当前实现）

- **判据来自任务声明**：`goal.success_criteria`，规划器按指令写；白名单外的判据被丢弃。
- **运行时只做三件事**：实时评估（`target_fill` / `target_distance`）、播报状态变化、拒绝与已满足
  判据背道而驰的动作（有界收尾）。**没有声明就不判、不拦、不播报**——运行时不发明标准。
- **`hold_s`（hold_for）**：判据需持续成立够久才作数；未满时状态里注明"需持续 X s 才作数"。
- 位置类判据（`position_reached`/`landed`/`flying_at`）出现时，不做"占画面比例"的判定——那由
  收尾校验负责，不满足就如实报未达成。

## 4. 第二份调研：成功检测 / 进度监控（同一天完成）

要点（结论与上面一致，但给了可抄的机制与代价）：

| 机制族 | 代表 | 零训练可用？ | 代价 / 失效模式 |
|---|---|---|---|
| 训练过的成功分类器 | SuccessVQA、AHA、AutoEval、RoboReward、Robometer | ❌ 要标注+训练 | 跨场景泛化差（SuccessVQA 域外 59%、AutoEval 每场景要 ~1000 张标注，还有漂移） |
| 零样本 VLM 判定 | TOPReward（token 概率探测）、GVL（帧序学习）、RoboVQA | ✅ | **零样本成功率接近瞎猜**（Flamingo ~50%）；依赖模型（AUC 0.43 vs 0.965）；必须给评分要点与证据要求 |
| 学习型 world-model / 隐状态探针 | Foresight、SAFE、ReconVLA | ❌ 需要模型内部 | 闭源 VLM API 拿不到内部特征，**不在我们可选范围** |
| 任务规约形式 | PDDL 目标谓词、HTN 方法、行为树后置条件、**ReKep 约束函数**、**Code-as-Policies 检查函数**、Voyager 的 critic | ✅ | 谓词要能落到传感器；每类任务写一段代码会重演"按类型写死"的老毛病 |
| 运行时监控 | N 连测 + 滞回、SPRT/CUSUM、**停滞检测 + 升级阶梯**、conformal 阈值、诚实的预算终态 | ✅ | 阈值靠拍脑袋会误报；conformal 需要标定集 |
| VLM-as-judge 的坑 | AgentRewardBench（**没有 judge 精度超过 ~70%**，倾向于"顺着 agent 的说法说成功"）、SycEval（谄媚 58%）、MLLM-as-a-Judge（位置/长度偏差）、BlindTest（琐碎视觉题 58%） | — | **把结论放进问题里会显著抬高谄媚率**；单样本单帧判定不可靠 |

### 对我们的排序（已完成 ✓ / 待做）

1. ✓ **判据留在计划、运行时只评估**（已实现；两份调研都指向这一条）。
2. ✓ **判据是元组**：`metric + params + tolerance + hold_s + required`（`hold_s`/`required` 本轮实现）。
3. ✓ **无进展监控 + 升级阶梯**（本轮实现）：声明的必需判据连续多轮不改善 → 提醒换策略 → 否决重复动作 → 如实收尾；不含任何任务类型常数。
4. **证据门控的 VLM 验证器**（下一步，需要你拍板成本）：声明"完成条件 + 评分要点 + 要引用的证据"，由 VLM 判定，规则照抄文献里唯一的防坑套路——
   - **问题里绝不出现"已经完成了吗"这类引导**（谄媚率 61%→ 只能靠中立提问压下来）；
   - 必须**引用证据**（画面里的标记点/深度读数），运行时可拿 `airsim_locate_point` 复核该点；
   - **多次采样取多数**（≥2/3），并把 `unclear` 当成独立结论（再观察一次，而不是硬判成功）；
   - 调用预算：只在"声称完成"或阶段边界问，不是每轮问。
5. **判据账本 + 诚实终态**：逐判据记录 `satisfied/failed/unverified/not_attempted` + 证据 + 时间；`completed` 只在**所有必需判据满足**时给出，否则 `unverified`/`budget_exhausted` 并在报告里写清"哪些没验证"。我们已有 `verification_status` 与 caveat，缺的是逐判据账本与更细的终态名。
6. **确定性评测器库**（任务无关、只是被任务引用）：穿门=平面穿越（位置符号变化 + 横向在内沿内）、落点=`landed` + 到点水平距离、到达=球域（半径由任务给）。仿真真值（分割/`simGetDetections`）只用于评测对照，不进运行时。
7. **在自家日志上标定阈值**（conformal，零训练）：用 `src/data/task_runs/*.json` 让操作员标注历史"声称完成"的真假，按判据族调 `hold_s`/容差，使**假成功率 ≤ α**；定期重标（有实测漂移案例）。

### 反模式（写在这里防止后人踩回去）

1. 把"模型说完成"当唯一闸门（judge 精度 <70%，且会顺着 agent 的说法）。
2. 验证问题里带结论（谄媚率显著上升，且会持续影响后续判断）。
3. 单样本、单帧的语义判定（零样本接近瞎猜）。
4. 把 VLM 的绝对数值当标定过的奖励（实测 MAE 0.66–1.6/5）。
5. 靠手感定"N 连测"（应配滞回/裕度或 SPRT/CUSUM/conformal 界）。
6. 把"无法评估"当"满足"（要把终态降级为 unverified）。
7. 用同一个信号既优化又验证；自证自纠（无外部反馈）会退化。
8. 无限打磨/重试（Voyager 是 4 轮上限；修复只在期望增益为正时做）。
9. 运行时的任务类型默认值（已移除；文献同样批评手写终止启发式）。
10. 设计依赖模型内部的监控（闭源 API 拿不到）。
11. 把安全监控与进度监控混为一谈（停滞绝不该触发"立即降落"）。
