# 创新点 01：完成判据契约（termination as a task-declared contract）

- **状态**：已实现 + 测试（`src/agent/agent_loop.py`、`src/agent/llm.py`；测试
  `tests/test_operator_visibility.py`）
- **一句话**：**"什么算做完"是任务声明的一份可机械评估的契约**，运行时只负责评估、播报、
  据此拒绝背道而驰的动作；**没有声明就不判**——运行时不发明标准。

## 问题（我们踩过的三版）

1. 运行时写死常数（"目标占画面 ≥25% 才算到位"）→ 把靠近类任务的标准强加给所有任务。
2. 运行时按任务类型兜底 → 仍然是运行时替任务发明标准（操作员明确否掉）。
3. 只让模型自己判断 → 实测"无限逼近"：28 步撞上限、任务被中断
   （VLA-SCT 把同一现象写成领域结论，见 `../papers/vla-sct-2602.01811.md`）。

## 我们的做法

- 判据写在计划里（`goal.success_criteria`），**闭集词汇 + 参数 + 容差 + 持续时长 + 必需性**：
  `{metric, params, tolerance, hold_s, required}`，未知 metric 会被丢弃（LLM 不能扩大验证器词汇）。
- 现有 metric：`target_fill`、`target_distance`、`position_reached`、`flying_at`、`landed`、
  `target_confirmed`、`photo_taken`、`status_ok`、`mission_progress_complete`、`formation_stable`。
- 运行时行为：评估 → 状态变化时播报（"完成判据 target_fill：未满足（fill=0.10 min_fill=0.25）"）
  → 判据满足后拒绝继续逼近的大步动作 → 有界收尾。位置类判据出现时不做"占画面比例"判定。

## 文献支撑与差异

| 文献/项目 | 它怎么做 | 我们的差异 |
|---|---|---|
| VLA-SCT（arXiv:2602.01811） | 训练无关的**启发式**终止模块（面向机械臂） | 我们把终止提升为**任务契约**（可声明、可审计、可用不同 metric 组合） |
| PDDL 目标谓词（LLM+P arXiv:2304.11477） | 目标公式即完成条件，符号求解器校验 | 我们的谓词**落在传感器上**（深度/视觉/遥测），无需环境模型 |
| ReKep（arXiv:2409.01652） | VLM 生成 Python 约束函数（每任务一段代码） | 闭集判据替代任意代码：UAV 上可审计、无需沙箱 |
| ProgPrompt（progprompt.github.io） | LLM 写断言检查前置条件 | 同上，且我们区分"必需/可选"与"持续成立" |

## 实验设计（毕设可做）

- 场景：靠近/悬停、落点、穿门、搜寻、拍照 5 类，各 10 次。
- 对照：A) 模型自判完成；B) 判据契约 + 运行时评估。
- 指标：任务完成率、**冗余步数**（完成后再动作的步数）、假完成率（声称完成但判据未满足）、
  决策轮数、总耗时。日志现成（`src/data/task_runs/*.json`）。
- 预期：B 的冗余步数与假完成率显著下降，决策轮数下降。

## 可写成论文的句子

> 我们将"任务完成"表示为一组由任务声明、运行时机械评估的判据契约，使终止判定与策略解耦，
> 并给出"运行时不发明默认标准"这一设计纪律；在 UAV 仿真任务集上，与模型自判相比显著减少
> 冗余动作与假完成。
