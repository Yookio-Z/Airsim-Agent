# 创新点 03：证据门控的 VLM 语义验证器（待实现）

- **状态**：设计完成，**未实现**（需要操作员确认 VLM 调用成本）
- **一句话**：让任务声明"用一句话描述的完成条件 + 评分要点 + 需引用的证据"，
  由 VLM 在中立提问下判定，且**每一句"满足"都必须引用画面里的证据**，运行时可复核。

## 问题

有些完成条件只有视觉能判（"穿过门框"、"标记居中"、"目标朝向正对"）。但文献给出的坑很多：
- LLM judge 判 agent 成功**精度上限不高**，且会顺着 agent 的说法说成功（AgentRewardBench，见
  `../papers/agentrewardbench-2504.08942.md`）；
- 把结论放进提问会显著抬高谄媚率（SycEval：预先下结论时 61.75%）；
- 单样本单帧的语义判定不可靠（BlindTest：四个头部 VLM 平均 58% 于琐碎视觉题）；
- 零样本 VLM 判"任务成功了吗"接近不可用（SuccessVQA 一系的工作都要标注适配）。

## 我们的做法（照抄文献里唯一成体系的防坑套路）

1. **中立提问**：问题里绝不出现"是否已经完成/是不是成功了"；只问与该判据对应的事实
   （"画面中央偏右是否有蓝色门框的横梁？它的中心在归一化坐标的什么位置？"）。
2. **强制证据**：要求返回 `{verdict: yes|no|unclear, evidence: {mark_id|bbox_hint, 它说明了什么}}`；
   `yes` 必须带证据，否则按 `unclear` 处理。证据可被运行时复核（拿到点后用 `airsim_locate_point`
   重投影，与之前的世界坐标比对是否一致）。
3. **多样本多数**：≥3 次采样，取 ≥2/3；采样顺序打乱以抵消位置偏差（MLLM-as-a-Judge 报告过 88% 的
   顺序复制）。
4. **`unclear` 是独立结论**：不是"失败"，而是"再观察一次"（换位置/换角度后重问），
   绝不当成功处理（AbstentionBench：模型不会主动说"不知道"）。
5. **预算**：只在"声称完成"或阶段边界调用，不是每轮；配合 `hold_s` 做滞后确认。

## 与其他方案的关系（为什么不用训练型检测器）

Inner Monologue / SuccessVQA / AHA 都训练了成功检测器，精度更高但要标注与训练（AHA 用了 4.9 万
对样本才到 70%），且跨场景泛化差（SuccessVQA 域外 59%）。我们的卖点是**零训练 + 可审计 + 证据可复核**，
因此明确不承诺同等精度，而是靠"证据 + 多数 + 未知不判成功"把假成功率压下来。

## 实验设计（毕设重点）

- 构造**成对的真假完成样本**（同一任务下：真完成 / 差一点 / 明显没完成），每类 ≥30 例，
  人工标注为金标准。
- 指标：**假成功率**（把没完成判成完成，最危险）、漏判率、`unclear` 占比、每次判定的 VLM 调用数。
- 对照：单次提问（含引导语） vs 我们的中立+证据+多样本；再叠加 `hold_s`。
- 校准：用历史运行日志（`src/data/task_runs/*.json`）做 conformal 式阈值标定，报告"假成功率 ≤ α"。

## 可写成论文的句子

> 我们给出一个零训练、证据门控的语义完成判据：判定问题保持中立、判定结论必须携带可被运行时
> 复核的视觉证据、并对不确定结论显式建模；在自建的真假完成样本集上，其假成功率显著低于
> 直接询问"任务是否完成"的基线。
