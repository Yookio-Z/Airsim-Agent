# 创新点 02：无进展监控 + 升级阶梯（stagnation ladder）

- **状态**：已实现 + 测试（`agent_loop._stall_reason` / `_is_repeat_action`；
  测试 `tests/test_operator_visibility.py::test_stall_is_detected_and_ends_honestly`）
- **一句话**：对**任务声明的必需可测量判据**做无进展检测——连续多轮没有改善就升级处理：
  提醒换策略 → 否决"与刚做过完全相同的动作" → 仍无进展则**如实收尾**（判据未满足会写进报告）。

## 问题

判据说了"什么算完成"，但没说"**一直完成不了怎么办**"。实测（2026-10-13）：
模型在同一位置反复微调逼近，28 步撞上限；另一例是反复读深度/状态空转 6 轮。
文献侧的对应结论：VLA"缺乏识别完成的能力→冗余动作与超时"（arXiv:2602.01811）；
自纠/重试必须有**有界停止规则**（Voyager 4 轮上限；VRR-Stop 只在期望增益为正时修复）。

## 我们的做法（不含任何任务类型常数）

- 只对**声明的、必需的、可测量的**判据生效（`target_fill` / `target_distance`）；
  没声明判据的任务永不触发。
- "改善"按判据方向定义：`target_fill` 越大越好、`target_distance` 越小越好；改善量小于裕度
  （0.05 / 0.5 m）即计入"没有改善"；判据满足即清零。
- 升级阶梯：连续 `_STALL_WINDOW=4` 轮无改善 → 播报"请换策略"；若该步与最近执行过的动作
  **同工具同参数** → 否决并交回模型；连续 `2` 个停滞窗口 → 按现状收尾（终态仍由判据校验，
  不会谎报成功）。

## 文献支撑与差异

| 文献 | 机制 | 差异 |
|---|---|---|
| CUSUM（Page）/ SPRT（Wald） | 变化点检测 / 序贯检验，有 α/β 控制 | 我们用最简形式（裕度 + 连续计数）；**升级阶梯**是我们加的 |
| 停滞检测（arXiv:2101.12054；PUL-SLAM arXiv:2511.04180） | 检测到局部最优后升级探索 | 我们把它搬进 agent 控制循环，并绑定"任务声明的判据" |
| Voyager（arXiv:2305.16291） | critic + 4 轮上限 | 我们不用 critic（成本），用测量值的单调性 |
| VRR-Stop（arXiv:2607.17641） | 期望边际增益为正才修复 | 我们的"重复动作否决"是它的廉价近似 |

## 实验设计

- 构造三类卡壳：目标不可达（判据永远不满足）、判据测量抖动、模型重复同一动作。
- 指标：**收敛到终止的步数**、冗余动作数、假完成率、"卡住被发现"的延迟（轮数）。
- 对照：无监控（现状）vs 有监控。
