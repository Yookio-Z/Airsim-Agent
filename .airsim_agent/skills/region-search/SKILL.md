# 区域搜索与跟踪指导

## 目的

指导"搜索 → 确认 → 跟踪"任务：**视觉模型是唯一能说出目标在不在这里的传感器**，每次
观察都是一次模型调用，代价 **10–20 s**。核心纪律是严格的观察预算、观察之间要飞行、
以及诚实的"没找到"——这样任务才不会退化成在原地反复问同一个问题。

Agent 负责决策和飞行；相机与深度工具都是只读的。

**高度纪律**：机载相机前视且略下俯。整个搜索/确认/跟踪阶段保持 **2–3 m**（绝不低于
1.8 m，绝不超过 3.5 m）。飞得更高会让视线俯角变大，目标缩成几个像素，视觉模型就分辨
不出来了。这类任务起飞到 3 m——不是通用的 5 m / 8 m 巡航高度。**站离/步长/相机常数的
权威定义在 `visual-approach` 的「相机几何」块**，本技能只引用这组数字。

**不要假设目标的位置。** 每次任务都从"目标大概率不在画面里"开始。绝不根据对话记忆或
上一次运行假设目标就在正前方。没找到就主动搜；还是没找到，就如实报告。

**观察预算（硬性）：** 一次观察 = 一次 `inspect_current_frame` 调用、**一个**直接问题
（"画面里有没有<目标>？在哪个方位（左/中/右）？离得近还是远？"），每次 10–20 s；
**每个位置最多 8 个朝向**、每次任务**最多 3 个位置**——24 次观察，已经是好几分钟。
**绝不在同一位置重复问**：答案含糊或否定，说明角度或距离不对，先转到一个新朝向或
飞到一个新位置。

## 意图 → 工具

| 意图 | 工具 | 说明 |
|---|---|---|
| 相机/帧健康 | `perception_status` | `online`、`fps`、`capture_age_s`、`view`——只看相机健康 |
| 目标在这个视野里吗？ | `inspect_current_frame` | **看到目标的唯一途径。** 每个位置一个直接问题 |
| 到已见目标的距离/绝对位置 | `locate_image_point` | 归一化点（可多给几个取中值）→ `distance_m`、`world_pos`（NED）、`valid`；便宜，走任何一步前都读 |
| 留存一张证据帧 | `inspect_current_frame` | `save_frame=true`（分析的同时存盘） |
| 转向扫描朝向 | `drone_rotate_to` | 绝对 `heading`，单位度 |
| 飞到搜索环上的点 | `drone_fly_to` | 本地 NED；`z` 保持在 −2.5 … −3.0 |
| 短距离重新定位 | `drone_move_relative` | 机体系，保守（1–2 m） |
| 观察/重看期间保持位置 | `drone_hover` | 每次观察前先悬停 |

## 决策逻辑

```
从当前朝向看一眼（inspect_current_frame）
        |
        ├─ 看见目标 → 在同一次回答里确认身份；读它那一点的深度；
        │   然后每个观察/位置做一次**按该深度计算**的有界接近步
        │   （绝不是固定的米数），或
        │   把完整接近交给 visual-approach 技能
        │
        ├─ "好像有" / 太远 / 说不清 → 不要在这里再问。要么走一步按深度
        │   计算的有界接近步再看，要么转向下一个朝向。最多 3 轮
        │   接近-再确认
        │
        └─ 什么都没有 → 下一个朝向（每位置 ≤8 个）→ 下一个环上位置（≤3）
                 → 诚实的"没找到"
```

## 工作流程

```
1. 准备：drone_get_status——要求 connected 且心跳新鲜。
   未在飞：drone_takeoff(altitude=3) 并轮询 get_status 直到 flying=true。
   "已升空"指 flying=true，而不是高度读数非零（读数可能是旧的）。
   连接最多重试一次；仍然失败就立刻上报。
2. 感知自检：perception_status——要求相机链路 online 且帧新鲜。
   离线或 `capture_age_s` 持续增长，停止任务并上报；不要空转。
3. 搜索（主动搜——绝不假设目标在正前方）。每个朝向只看一次，绝不看两次：
   a. 原地扫描（第 0 轮）：drone_rotate_to 以 45° 步进（0→45→…→315）——
      最多 8 个朝向。每个朝向：悬停、等 2–3 s 稳定，然后看一次。
      看见目标 → 进入第 4 步。整圈什么都没有 → 飞到环上。
   b. 扩大环：总共最多 3 个位置——起点加最多 2 个环点，每次更远、保持在
      同样的 2–3 m 高度，例如 drone_fly_to(8, 0) 然后 drone_fly_to(16, 0)
      （本地 NED，z 保持 −2.5 … −3.0），沿上一轮扫描看起来最有希望的那个
      朝向飞。每个点：稳定 2–3 s，然后重复 8 朝向扫描。
      （8 朝向 × 3 位置 = 整个预算：24 次观察，好几分钟的模型时间。）
   c. 分辨率极限：超过约 25 m，小目标只有几个像素，视觉模型会说"看不清"。
      在得出"这里没有"的结论前，先飞到目标嫌疑点 15 m 以内。
   d. 预算耗尽仍什么都没有 → 报告"没找到"。绝不编造目标。
4. 确认（一次观察）：一个直接的属性问题
   （"那辆车的颜色/特征是不是<目标>？"），从同一次回答里读
   bbox_hint {x, y, w, h}。已经近到能辨认，就悬停并汇报。还很远，
   就做一次有界接近步：它那一点的深度（3–5 个点的中值）→ 按该距离计算
   的前进步（visual-approach 的算术；绝不是固定 3 m）——每个新位置
   一次观察，最多 3 轮。绝不飞向未知坐标。
5. 跟踪 / 保持（确认之后）：让目标保持在 2–3 m 距离和画面内。
   a. 每一步之前读它那一点的深度；只有在目标可见且居中时才用
      drone_move_relative 或 drone_fly_to（z 在 −2.5 … −3.0）走步。
   b. 想要绝对锚点？locate_image_point(x, y) 给出它的 `world_pos`（NED）
      ——可选，用于飞到该点或之后重新找到目标。
   c. 目标离开画面：转回它最后的方向，只看一次。
      30 s 内见过 → 继续。超过 30 s 或两次观察失败 → 报告"目标丢失"并停止。
6. 收尾：drone_land，然后汇总
   {搜索轮数、观察次数、目标描述、找到/失败、接近轮数}。
```

## 核心规则

- **每次感知检查之后必须跟一个飞行动作或一次状态回读。** 不允许连续的空查询。
- **观察预算**：每个朝向一次观察、每位置 ≤8 个朝向、≤3 个位置、每次观察一个问题。
  绝不在同一位置重复问。连续两次含糊的答案意味着角度或距离错了——移动或转向。
- **对中心是 Agent 的职责。** 没有任何东西会自动帮你把目标放到画面中心。用
  `drone_rotate_to(heading_deg = current + (x − 0.5) × 90°)`，角度来自
  `visual-approach` 的 90° 相机几何块（目标在中心右侧 15% → 约 +13°）。
  只有偏航可用；垂直构图由固定的 2–3 m 高度决定。
- **飞行失败**：任何飞行工具报错（arm / takeoff / fly_to / land），最多重试
  **一次**，然后停止任务并报告 `{阶段、工具、错误、建议}`。典型原因是链路不可用。
- **链路自检**：起飞前用 `drone_get_status` 确认 `connected` 且心跳新鲜。链路失败就停下
  并上报——**不要自行重连**（重连由运行时守卫处理）；相机连续两次离线，停止并上报。
- **绝对坐标只能来自 `locate_image_point`**（`world_pos` 是 NED）。要朝一个已定位
  的目标飞，用它的 `x`/`y`，`z` 取 −2.5 到 −3.0 之间；绝不逼近到 2 m 以内。
- **搜索边界**：没有明确区域时，在起点 ±15 m 内活动；任何单段航程不超过 8 m；
  总路径不超过 120 m。
- **时间**：目标 180 s 内完成——但用完整个观察预算已经是好几分钟，宁可提前降落也不
  要超时。
- **高度与安全**：全程 2–3 m（绝不低于 1.8 m，绝不超过 3.5 m）。出现任何异常，先悬停
  再上报。

## 失败处理

- 相机链路离线或帧过期时，停下并上报。
- 看见的目标既没有有效深度、也没有有效的 `locate_image_point` 结果时，停下并上报，
  不要盲飞。
- 观察预算用完后，诚实地报告"没找到"，而不是声称找到了目标。

## 不适用

- 感知/相机服务离线时做搜索（先报告故障；用 `flight-sequence` 升空并检查链路）。
- 动态避障（AirSim 场景基本是静态的；高度纪律和深度检查就是防护）。
- 真机上的精确降落（仿真验收后需要重新标定）——用 `flight-sequence`；降落在小物体上
  由 `visual-approach` 覆盖。
- 多机区域覆盖——用 `formation` 技能。
