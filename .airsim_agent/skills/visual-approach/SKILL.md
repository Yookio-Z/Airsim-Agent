# 视觉接近（视觉模型 + 深度）

## 目的

这是唯一且仅有的接近路径：操作员指着画面里看得见的东西，无人机飞过去。**视觉模型
负责语义（那是什么、大致在哪、看起来多大），深度相机负责米制距离**，每一步都是按
实测距离计算出的、有界的、经复核的机体系步长。

**让这套流程安全的规则**：步长**由深度读数算出**，不是固定值——距离远就走大步，
靠近后步长自动收缩，且绝不越过 2 m 站离。视觉模型给的点与大小明确是*粗估*
（±30% 的估计值），所以目标在画面里还很小（`h < 0.10`）时，每一步还被限制在
**剩余距离的三分之一**以内，下一步之前必须重读深度。绝不手算世界坐标——
`locate_image_point` 是唯一被许可的途径，而这个有界的机体系循环根本不需要它。

## 相机几何 —— 90° 常数（其他技能引用本块）

我们的前视相机：**水平视场角 FOV = 90°**，4:3 画面（彩色 800×600，深度 256×144）。

- `tan(fov_h/2) = tan(45°) = 1`，所以水平像素-米系数正好是 2：
  - 米制横向偏移 ≈ `Z × (x − 0.5) × 2`，
  - 米制宽度 ≈ `Z × w × 2`，
  - 米制高度 ≈ `Z × h × 2`（垂直半角约 37°，tan ≈ 0.75，所以高度会偏大约 30%——
    在 `h` 本身只是粗估时，这个精度够用）。
- 把归一化坐标为 `x` 的点转到画面中央所需的偏航角：`Δheading ≈ (x − 0.5) × 90°`
  （x = 0.65，即画面中心右侧 15% → 向右转约 +13.5°）。
- `Z` 始终取 `locate_image_point` 在目标点上的 `distance_median_m`（多点中值）。

## 两步循环

```
1. 问视觉模型要一个点和一个粗估大小（一次调用，10–20 s）
   inspect_current_frame(
     "画面里那个<目标>在什么位置？给出它的中心归一化坐标和大致宽高
      bbox_hint {x, y, w, h}：x=0 最左、1 最右；y=0 最上、1 最下；
      并说明它是什么、朝哪个方向。")
   → answer.target_candidates[0].bbox_hint = {x: 0.36, y: 0.52, w: 0.08, h: 0.12}
   w、h 是**粗估**（schema 里就叫 rough）：当作 ±30% 的估计，永远不要当测量值用。

2. 在这个点上量距离（便宜，毫秒级；一个几何工具，深度+位姿一次算清）
   locate_image_point(points="0.36,0.52;0.355,0.525;0.365,0.515")
   → distance_m（主点） / extra_measures[].distance_m  +  distance_median_m
   **用归一化（0..1）坐标**（彩色 800x600 vs 深度 256x144——彩色像素会静默地读到
   另一个位置，返回一个看似合理的错误距离），并且**围绕目标查 3-5 个点**，取
   distance_median_m：单个深度像素经常落在物体边缘上。

2b. 用目标的视觉大小反查深度（移动之前）
   深度图分辨率只有彩色的 1/9：远处的目标在彩色图里有 20-40 px 高，在深度图里只有
   1-2 px，所以一个"看起来在目标上"的点常常落在**背景**上。比较两个独立估计：

     z_size ≈ 目标的真实高度_m / (h × 2)      # 小孔成像反推，用上面的 90° 常数
                                              # 人≈1.7 m，车≈1.5 m

   |distance_median_m − z_size| > z_size 的 50% → 很可能打在背景上：**不要移动**——
   重新把点对准目标内部再读一次。实测案例（2026-10-12）：模型猜"30–50 m"，深度读到
   71 m（后面的楼），而视觉大小反推约 21 m——三个数里错了两个，这个检查能抓住它。

3. 走一步有界步长（机体系，米）
   tan(fov_h/2) = tan(45°) = 1，所以取 Z = distance_median_m、x = 归一化横向中心：

     right_m   = Z × (x − 0.5) × 2      # 横向偏移，fov=90° 时是精确值
     forward_m = Z × 0.97               # ≈ Z·cos(15°) 俯角修正；目标靠近画面上下边缘时
                                        #   垂直分量会混进来，这个估计会变差（所以每步要复核）
     remaining = max(0, forward_m − 2.0)   # 留 2 m 站离，绝不贴上去
     step      = clamp(remaining, 0, 12.0) # **一步走多远由实测距离决定**，不是固定步长：
                                           #   远则长（上限 12 m），近则自动缩短，到站离为止
     目标还小（h < 0.10）时：step = min(step, remaining / 3)   # 点/大小是粗值，近处别赌
     right     = clamp(right_m, −3.0, 3.0)
   → drone_move_relative(forward_m=step, right_m=right, velocity=1.0)

   已知距离不需要每步都问视觉模型：**深度每步读**（毫秒级，也是"墙/障碍"的探测），
   视觉模型**每 3 步复核一次**，或在中位距离不再下降、横向偏移突然变大时立刻复核。
   距离 0.5 m 左右就该停：**够近是"到站离"，不是"走完固定米数"**。

4. 复核纪律（每类边界上强制执行）
   - 每步：locate_image_point 在目标点上重读（距离是下一步的前提，也是障碍探测）
   - 每 3 步：视觉模型再问一次"画面中央偏<方向>的那个<目标>还在吗？还是同一个吗？"
   - 距离不再下降 / 目标不见了 / 复核说不清 → STOP 并报告，不要继续走
```

2026-10-12 对照本项目自己的几何验证过：30 m 处，视觉模型点位 ±20 像素的误差
≈ 横向 ±1.2 m——相对于按距离算出的步长不算大，但它会*累积*，所以才需要这些纪律：
走之前目标必须在画面中央；只有目标还远时才允许走大步（且不超过剩余距离的三分之一）；
每一步之后都必须重读深度。

## 工作流程

```
1. 先升空：drone_get_status → 若未在飞，drone_takeoff(altitude=3) 并等到
   flying=true；全程保持 2–3 m（前视相机）。检查相机链路
   （perception_status：online、fps、capture_age_s）——帧过期任务就停。
2. 看一眼（第 1 步）：记录点**和**粗估大小。绝不在同一位置问两次——答案含糊
   说明角度或距离不对，先移动或转向。
3. 在该点读深度（第 2 步），取 3–5 个点的中值，加上合理性检查（第 2b 步）。
   distance_m 缺失或离谱 → STOP：没有距离就没有有界步长。
4. 目标偏离画面中心很远时先转向对准（drone_rotate_to，用 (x − 0.5) × 90°）：
   转向比横移更快也更安全。
5. 走一步（第 3 步）。每走下一步之前重读深度，每 3 步重问一次视觉模型（第 4 步）。
   中位距离不再下降时停。
6. 目标**大到足以辨认**时收尾：粗估归一化高度 h 达到目标的占画面比例（默认 0.25
   ——画面高度的四分之一）。因为 h 是粗估，h ≥ 0.20 算"在阈值 ~20% 以内"：只有在
   深度确实也下降了的时候再走一步，然后停。永远不要追固定的米数。然后
   drone_hover 并汇报 {目标、步数、首次/末次距离、最终状态、触到的上限}。
   "直到满意为止"式停止条件见下文"循环直到满意"。
```

## 循环直到满意（"直到满意为止"）

当操作员的停止条件是一个*质量*而不是步数时（"靠近到满意"、"够近为止"、"看清楚那个
人的样子"），不要在第一个循环后就收敛：

```
repeat:
  1. 观察：inspect_current_frame（点 + 粗尺寸 + 描述）
  2. 判断：目标的归一化高度 h 够了吗？—— h ≥ 0.25 或操作员给的条件，不是固定米数
     够 → drone_hover + 汇报（几步、最终距离、最终状态、有没有触到上限）
     不够 → 继续
  3. 动作：深度读取（每轮）→ 一次 ≤3m 的有界步（或先 drone_rotate_to 对准）
  4. 放弃条件：连续 2 轮中位距离没下降（没在靠近 / 被挡住），或连续 2 次复核
     说不清目标 → 停下并如实汇报
```

循环本身由运行时提供（计划的 `keep_reacting=true`）：每轮都要**基于新观察**重新判断，
而不是重发同一个动作。硬上限约 28 步，所以每轮都要有进展，触到上限就如实收尾。

## 穿过开口（门框 / 门洞 / 窗户）

先把开口对准中心，证明它足够宽，然后用短的、每步复核的步伐穿过去。

1. **对准中心。** 看一眼："画面里那个门框/开口的中心在什么位置？大致宽高是多少？"
   → `bbox_hint {x, y, w, h}`。用
   `drone_rotate_to(heading_deg = current + (x − 0.5) × 90°)` 转向——即上面的
   像素偏移 × 半视场角换算。转向之后再看，绝不从同一朝向看第二次。
2. **移动之前先查净空。** 只读中心一个点，只能证明远处*有*一个面，不能证明路是通的。
   以 ±0.1 归一化偏移采样中心与周围四点：

   ```
   locate_image_point(points="0.50,0.50;0.40,0.50;0.60,0.50;0.50,0.40;0.50,0.60")
   ```

   中心是主点（`distance_m`），周围四点在 `extra_measures[]` 里逐点给（最小读数即
   `distance_min_m`）。设 Z_open = 中心读数：如果**任何**一个周边点比它近约 40% 以上（`< 0.6 × Z_open`），
   说明有东西挡路——**STOP**，不要前进。重新对准中心、换个高度（±0.5 m）再试，
   或报告开口不通。
3. **洞够大吗？** 无人机约 0.5 m 宽；开口米制宽度 ≈ `Z_open × w × 2`。估计宽度低于
   约 1.5 m 时余量太薄——**报告而不是尝试**（`w` 是粗估，"1.6 m"可能是个 1.1 m 的洞）。
4. **以 ≤2 m 的步长穿越。** `drone_move_relative(forward_m=2, velocity=1.0)`，下一步
   之前重读中心点（和 4 个偏移点）的深度。开口必须保持大致居中：`|x − 0.5| ≤ 0.15`。
   漂出这个范围就停下，先用 `drone_rotate_to` 重新对准再移动。
5. 当开口的深度跳到"在身后"（远侧占满画面），停下，做一次确认性观察
   （"开口还在身后吗？前方有什么？"），然后继续任务或悬停汇报。

## 降落在小物体 / 停机垫上

降落是唯一一个被有意放弃 2 m 站离的场景——但必须以每一步都在目标点上新读的深度
为代价。

1. 接近到物体居中且 `distance_median_m` 为 2–3 m，然后 `drone_hover`。下降期间不要
   继续前移。
2. 可选：取它的绝对位置：`locate_image_point(x, y)`（`x`,`y` = 物体的归一化点）→
   `world_pos`（NED）、`distance_m`、`valid`。用它 `drone_fly_to` 到该点正上方再下降，
   或用于之后重新找到这个物体。`valid` 为 false 就跳过——下面的下降本身是站得住的。
3. 以 0.5 m 步长下降：`drone_move_relative(up_m=-0.5)`，然后在物体点上重读深度
   （点过期、物体在画面里移动了就重问视觉模型）。**绝不在没有新深度读数的情况下
   下降。**
4. 出现任一情况就停止下降：物体在画面里已分辨不出（相机前视，正下方的东西会离开
   视野），或它中心的深度低于约 0.6 m。
5. `drone_land`，然后汇报最终位置以及降落看起来是否居中。如果深度比上一步突然近了
   很多（下面有别的东西），悬停、停止下降并报告——不要降在一个不明表面上。

## 核心规则

- **单步 3 m 硬上限。** 粗估的视觉模型点是个弱参照；一大步会把小小的指点误差放大成
  几米的横向误差。
- **深度每步读，视觉模型每 3 步问。** 绝不在一次观察上连续执行两个动作而不在目标点
  重读深度。
- **深度是代码的事，算术是你的事。** 你可以读 `distance_median_m` 并用 90° 几何块
  计算 `right/forward/Δheading`；你**不**可以自己推世界坐标——那是
  `locate_image_point` 的职责，而且是可选的。
- **粗估始终是粗估。** `w`,`h` 是 ±30% 的估计；由尺寸推出来的数（`Z × h × 2` 等）
  只能用来判断"无人机过得去吗"这类问题，永远不能当测量值汇报。
- **没有距离就不移动。** 深度读数缺失/为零/不可信，这一步就停。
- **交叉检查框内外，别信单个探针。** 需要坐标时，用视觉模型的粗框调
  `locate_image_point(x, y, w, h)`：它在框*内*和框*外*各采样深度，告诉你这个框是
  一个独立物体（`object_in_front`）还是一整片连续表面（`same_surface`——你画的是
  马路/墙，不是那辆车），并给出米制尺寸（`metric_size`）供把关（"一辆车约 1.8 m
  宽，不是 0.4 m"）。`same_surface` 或尺寸离谱 = **重新对准，不要移动**。
- **定位点是探针，不是目标。** `locate_image_point` 返回的是深度射线打到的位置——
  相机下俯时那常常是目标*前面的*路面/建筑（实测：下俯 9° → 30 m 外的路面，不是车）。
  **绝不用 `drone_fly_to` 飞向这种点**：你会冲过头并把目标甩出画面。用有界的
  `drone_move_relative` 步逼近；如果必须飞向一个坐标，在离它**至少 2 m**处停下，
  并保持目标在画面内。
- **绝不信单次定位。** 一个定位点（或一个距离）来自单次观察的估计；走完一段之后，
  再调 `inspect_current_frame` + `locate_image_point` 更新它。两三轮"走一半 →
  重估"能收敛到目标，而一次"直飞估计点"会把目标丢掉。
- **目标丢了？退回去看，别在原地继续找。** 转向它最后已知的方位（或后退/略升高），
  从一个它应该会在画面里的位置重新看。在同一个点反复看只会持续失败。
- **停下并报告**：3 步没有收敛后、两次模糊的视觉回答后、或目标方向一变得不清楚时。
  报告实际到达了什么，而不是本来想做什么。
- **对中心是 Agent 的职责。** 没有任何东西会自动把目标放到画面中心：你用
  `drone_rotate_to` 加像素偏移算术来偏航。只有偏航可用——垂直构图由固定的 2–3 m
  高度决定。

## 失败处理

- 视觉模型说"有东西"但该点深度无效 → 点很可能落在天空/边缘上；让它给一个更贴近
  物体本体的点。
- 连续两步没有让中位距离下降 → 停：你没有在收敛，很可能指错了东西或被挡住。
- 视觉模型自相矛盾（"现在它变成另一辆车了"）→ 停下并报告；不要继续在你已无法辨认
  的目标上迈步。
- 对只是查看的目标，绝不要靠得比 2 m 更近；上面降落一节是有意的例外，且它带着深度
  下降。
- 相机帧过期（`perception_status.capture_age_s` 增长）→ 任务停止。

## 不适用

- 搜索（"在某处找一辆车"）→ 用 `region-search`。
- 多机任务 → 用 `formation` 技能。
- 不需要移动的语义问题（"这是什么颜色？"）→ 直接调 `inspect_current_frame`，
  不需要接近循环。
- 手算目标的 NED 坐标 → 手推算不出来；真需要绝对坐标时用 `locate_image_point`。
- 真机飞行：每一步都需要操作员批准的边界。
